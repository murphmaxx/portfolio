# Content & Evidence Model

This is the planned content contract for the portfolio. It contains no final public claims.

## Project record

Each project record must eventually include:

- display name
- canonical repository URL
- one-line thesis
- category / capability area
- current status
- role and contribution
- system boundary
- implementation stack
- evidence links
- demo media and poster
- verification method
- limitations / not-built list
- next direction

## Evidence classes

- repository source
- README or design specification
- reproducible test output
- screenshot or recording of real software
- technical paper or research artifact
- benchmark with method and scope
- threat model, evaluation, or audit record

## Claim policy

A claim is not published merely because it sounds plausible. Every claim must either point to evidence or be stated as an explicit design intention, experiment, draft, or limitation.

## Media contract

Every production demo must have:

- source capture or authored scene
- render command / version
- poster frame
- captions or transcript
- reduced-motion still
- note distinguishing real behavior from explanatory animation
