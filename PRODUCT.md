# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

delegated: begin with a static HTML/CSS/JS GitHub Pages scaffold because the first deliverable is a design system and mockup archive, not a content-heavy application. Reassess Astro or another static generator when the approved direction and content model are ready.

## Users

The primary audience is recruiters and hiring managers evaluating AI security and safety engineering work. They should be able to understand the practitioner's direction, inspect credible evidence of work, and decide whether to continue to a repository, project detail page, or contact path.

## Product Purpose

A GitHub-backed portfolio and near-electronic résumé for technical projects, research, and production-quality demonstrations. It should connect public professional positioning to inspectable project evidence without exaggerating project status or capabilities.

## Positioning

The portfolio connects governed execution, human control surfaces, local auditable AI, model interpretability, deterministic software evidence, and technical writing into one coherent body of work.

## Operating Context

The repository is the source of truth for the static website, project records, design decisions, operating standards, and future demo-video source files. GitHub Pages is the intended deployment target, but the initial scaffold remains public-ready without enabling Pages or publishing it.

## Capabilities and Constraints

- Homepage with a hero, professional direction, project index, research/writing area, and contact path.
- Dedicated project detail routes rather than modal-only detail views.
- Project cards will eventually link to richer technical explanations, repository links, and demo media.
- Candidate projects include Ouros, Canopy, Grounded, Eyeofrah, Crucible, and The Cost of Asking.
- No final public content is being added during the design exploration phase.
- Project status, limitations, evidence, and verification must remain explicit.
- No secrets, private documents, credentials, unsupported claims, or invented metrics.
- Initial implementation should remain static, portable, accessible, responsive, and easy to maintain from GitHub.

## Evidence on Hand

Local repositories and README material exist for Canopy, Grounded, Ouros, Eyeofrah, and Crucible. The paper title The Cost of Asking is known, but its final public content and publication status are not yet supplied. The initial mockups intentionally use neutral blocks and no project copy or claims.

## Product Principles

- Evidence before assertion.
- Projects remain projects; do not inflate titles or status.
- Limitations are part of credibility.
- Motion explains systems rather than decorating them.
- The interface should make technical work easier to inspect.
- Public release follows explicit review and approval.
